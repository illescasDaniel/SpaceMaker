Lean agent context: `AGENTS.md` sole always-on source, path-scoped rules, memory archive.

- **Context:** The user asked to review the full loaded agent context (`AGENTS.md`, `.cursor`/`.claude` rules and skills, `memory/`) and reduce dilution/duplication. Measured before this change: `AGENTS.md` (14.4KB) plus five always-on `.claude/rules/*.md` (7.5KB) loaded every session — ~22KB before any work — on top of `memory/activeContext.md` (9.9KB) and `memory/progress.md` (6.4KB) read at session start. The same guidance was stated in 3–5 places each: phase gates in `AGENTS.md`, the `sdd` rule, the `sdd-feature` skill, and the `playbooks` rule/skill; the memory protocol in `AGENTS.md`, the `agent-memory` rule, the `agent-memory` skill, and `memory/README.md`; hexagonal layering in `AGENTS.md`, the `hexagonal-python` rule, and the `hexagonal-python` skill. `progress.md` also had stale entries (`docs/database.md`, which had been deleted; an "Open" header holding mostly `[x]` items).
- **Decision:** `AGENTS.md` is now the single always-on instructions file (both Cursor and Claude Code read it natively) — cut from 14.4KB to ~6KB, keeping only the hard rules, the compact phase-gate table, the memory-bank triggers, and a "where to look" index, with detail moved out. The four rule pairs that mostly repeated `AGENTS.md` (`agent-memory`, `sdd`, `playbooks`, `graphrag-tools`) were deleted from both `.cursor/rules/` and `.claude/rules/`; their content now lives in `AGENTS.md`, the `agent-memory`/`sdd-feature` skills, or the new `docs/agent-tooling.md` (Graphify advanced commands, rule-pairing maintenance notes, durable Windows/tooling gotchas). Only `hexagonal-python` remains a rule, rewritten as **path-scoped** (`globs`/`paths`: `src/spacemaker/**`) instead of always-on, absorbing the now-deleted `hexagonal-python` skill's placement table. `.cursor/skills/playbooks/` and `.cursor/skills/hexagonal-python/` were deleted as redundant with `AGENTS.md` and the rule, respectively. New `tests/unit/test_agent_context.py` runs in `uv run task checks` and asserts: every `.cursor/rules/*.mdc` has a `.claude/rules/*.md` counterpart (and vice versa) with byte-identical bodies after frontmatter and equivalent scoping (`alwaysApply: true` ⇔ no `paths`; `alwaysApply: false` + `globs` ⇔ matching `paths`); no Cursor-only rule kinds (description-only "agent requested", manual) are used, since Claude Code has no equivalent; `AGENTS.md` stays under a 130-line budget; and no tracked context file references the deleted rule/skill paths. `memory/progress.md` was cut to open items only; finished Done lists and old `activeContext.md` threads moved to new `memory/archive.md` (not read at session start, referenced from `memory/README.md`).
- **Rationale:** Repeated, lengthy guidance dilutes the rules that matter most (phase gates, the hexagonal import guard) and risks silent drift between the Cursor and Claude Code copies, since nothing previously checked they matched. The user explicitly requires Cursor and Claude Code to receive **equivalent** guidance — this is now enforced by a test rather than relying on remembering to hand-edit both files, and is also saved to Claude's cross-session memory so future sessions keep new rule pairs equivalent by construction. Loading only the essentials every session, with the rest one skill/doc-read away, keeps agent behavior sharp without losing any information — it's relocated, not deleted.
