Full `web/src/*.ts` typing pass: drop `R` registry, drop `@ts-nocheck`, scope Biome's new strict rules via `overrides`.

- **Context:** User flagged `function healIfStaleShell(settings)` (no types, `shell.ts`) and `import { R, S } from "./state.js"` (wrong extension) as symptoms of a broader gap: 13 of 18 `web/src` modules still started with `// @ts-nocheck`, and every module called shared helpers through a string-keyed global registry `R` (`R.foo = foo` assignments + `R.foo()` call sites — a runtime service locator) even though every function was already `export`ed and directly importable. This was inherited from the "Qualify bare cross-module shell helpers as `R.*`" / "Keep pre-rename `R.*` aliases" fixes below (2026-09-29), which patched around the registry rather than removing it. User chose (AskUserQuestion): switch relative imports to `./x.ts` (TS 5.9's `rewriteRelativeImportExtensions` rewrites them to `./x.js` in emitted output, so the importmap cache-busting scheme in `ui_shell.py` is untouched), and do the full registry removal (not just alias patching) — every `R.foo(...)` call site becomes a direct named import from the defining module.
- **Decision:** (1) Removed `@ts-nocheck` from all 18 `web/src/*.ts` files; every exported function now has explicit parameter/return types (DOM lookups narrowed with `instanceof HTMLButtonElement`/`HTMLImageElement` etc. rather than casts). (2) Deleted the `R` registry entirely — `RuntimeRegistry` removed from `types.ts`, `R` removed from `state.ts`; every call site imports the function it needs directly (`S`, the shared mutable state object, stays — it's genuine cross-module state, not indirection). (3) All relative imports rewritten `./x.js` → `./x.ts`; `web/tsconfig.json` gained `rewriteRelativeImportExtensions: true` plus `noUnusedLocals`/`noUnusedParameters`/`noImplicitReturns`/`noFallthroughCasesInSwitch`. (4) `types.ts` interfaces (gallery items/pages/exports, settings, jobs) were grounded in the actual FastAPI route / dataclass shapes rather than guessed. (5) `biome.json` adds `web/src/**/*.ts` to `files.includes` and turns on `noExplicitAny`/`noTsIgnore`/`noVar` as errors — but scoped to a new top-level `overrides: [{"includes": ["web/src/**/*.ts"], ...}]` block, **not** the top-level `linter.rules.suspicious`, because the latter applies those rules to every file `files.includes` already covers (`wireframes/**/*.html`, static `.js`) and produced 586 spurious errors (e.g. `var panels = {...}` in a wireframe) on files never meant to be held to the new bar. (6) New guard-rail test `tests/unit/test_web_typing.py` asserts no `@ts-nocheck`/`@ts-ignore`, no relative `.js` imports, and no `R.` usage anywhere in `web/src`. (7) `npm run build:web` regenerated `static/js/*.js`; the stale `static/js/ws.js` artifact (source `ws.ts` deleted in an earlier session) was removed manually since `tsc` never deletes orphaned outputs for sources that no longer exist. (8) Small unrelated Python fix folded in: `mcp-servers` added to ruff's targets (`scripts/quality/checks.py`, `scripts/quality/ruff.sh`) with a matching `mcp-servers/*/tests/** = ["S101","S603","ANN"]` per-file-ignore (mirrors the existing `tests/**` policy); surfaced a pre-existing pytest `test_server.py` module-name collision between `codenav_mcp`/`webnav_mcp` tests (confirmed via git-stash to predate this session, traced to commit `ef5d6e5`), fixed via `--import-mode=importlib` in `pyproject.toml` rather than adding `__init__.py` files (no test dir in the repo uses that convention).
- **Rationale:** An internal refactor with no UX/behavior change (existing DOM output, routes, and the importmap cache-busting scheme are all unchanged) — no wireframe/spec gate needed per `AGENTS.md`, logged here instead. Removing the registry outright (rather than continuing to alias/patch it, as the two entries below did) closes off the whole bug class those entries were fighting — a stale/missing `R.foo` alias can't silently break bootstrap again if there's no `R` to miss an alias on. Scoping the new Biome rules via `overrides` instead of raising the global severity keeps the stricter bar on new/migrated TS sources without retroactively failing legacy wireframe/static-JS files that were never part of this migration. `npm run check` (Biome + `tsc --noEmit`) and `uv run task checks` (ruff incl. `mcp-servers`, ty, pytest) both green; `tests/unit/test_web_typing.py` passes (5/5).
