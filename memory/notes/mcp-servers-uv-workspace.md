mcp-servers: turn `_shared`/`codenav_mcp`/`webnav_mcp` into a uv workspace of three installable packages.

- **Context:** Following the earlier standalone-reuse generalization (env-var config, no hardcoded SpaceMaker paths — see the 2026-09-28 entry below), the user asked to extract the ad hoc `tests/unit/test_mcp_nav_format.py` / `test_mcp_web_index.py` / `tests/integration/test_mcp_ty_search_smoke.py` into per-server folders under `mcp-servers/` so each server could be bundled standalone, then — when offered a choice between a light file move and a full package split — confirmed going further: making `_shared` "a small helper/shared package with its own tests" that the other two servers depend on as a real dependency, not just a shared folder.
- **Decision:** Restructured `mcp-servers/` as a uv workspace (`[tool.uv.workspace] members = [...]` in the root `pyproject.toml`) with three member packages, each moved to a `src/<pkg>/` layout via `git mv`: `_shared` → distribution `mcp-nav-shared` (import name kept as `_shared`, no runtime deps), `codenav_mcp` → distribution `codenav-mcp`, `webnav_mcp` → distribution `webnav-mcp`. The two servers declare `mcp-nav-shared` as a real dependency resolved to the local sibling via `tool.uv.sources = { workspace = true }`, not a copy-pasted folder. The root project depends on `codenav-mcp`/`webnav-mcp` as dev dependencies (also workspace-sourced) so `uv sync --group dev` installs all three editable into the one shared venv. Removed the `sys.path.insert(...)` hacks from both servers' `server.py` now that proper package imports resolve (`from codenav_mcp.ty_command import ...`, `from webnav_mcp import web_index`); `.mcp.json`/`.cursor/mcp.json` launch them as `python -m codenav_mcp.server` / `python -m webnav_mcp.server` instead of a literal script path. Each package's `pyproject.toml` uses the `uv_build` backend (matching the root project) with an explicit `[tool.uv.build-backend] module-name` for `_shared` (its distribution name `mcp-nav-shared` normalizes to a `mcp_nav_shared` module dir by default, which doesn't match the actual `_shared` import name) and its own `[tool.pytest.ini_options]` (`testpaths = ["tests"]`, `pythonpath = ["src"]`) so a bare `pytest` run from inside the package picks up its local tests instead of pytest walking up to the root's `testpaths = ["tests"]`. The original 955-line combined test file was split along module boundaries into `mcp-servers/_shared/tests/{test_format,test_workspace,test_lsp_client,test_errors,test_resolve}.py` and `mcp-servers/codenav_mcp/tests/test_server.py`; `test_mcp_web_index.py` and `test_mcp_ty_search_smoke.py` moved wholesale (via `git mv`) to `mcp-servers/webnav_mcp/tests/` and `mcp-servers/codenav_mcp/tests/` respectively, minus their `sys.path` hacks. `scripts/quality/pytest.sh` now also runs all three packages' `tests/` dirs. `docs/agent-tooling.md` gained a "Package layout (uv workspace)" section and had its full-path mentions of pre-move files updated to the new `src/<pkg>/` locations.
- **Rationale:** A real dependency (not a folder copy or a shared-but-uninstalled path hack) is what actually makes "release `codenav`/`webnav` standalone someday" credible — a consumer installing just `codenav-mcp` gets `mcp-nav-shared` pulled in properly instead of needing to vendor `_shared/` by hand. Module-mode invocation (`python -m pkg.server`) was a clean simplification that fell out of proper installation, independent of the standalone-release goal: no more manual `sys.path` surgery for sibling imports. Keeping the Python import names (`_shared`, `codenav_mcp`, `webnav_mcp`) unchanged while giving each package a distinct PyPI-style distribution name minimized code churn — only the build-system plumbing needed to know about the name split, not any importing code. Verified via `uv sync --group dev` (all three install editable), full `uv run pytest` (382 passed) and each package's tests run standalone from its own directory, `uv run ty check` (clean), and both servers starting successfully under `python -m <pkg>.server`.
