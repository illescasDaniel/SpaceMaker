codenav/webnav: fix live-smoke bugs, generalize for standalone reuse.

- **Context:** Live-smoking the tools added earlier the same day (`codenav/webnav: intent-level tools...`, below) surfaced 5 issues: `implementations("WebSocketLike")` matched itself (the exclusion only checked a literal `ports/` directory, not whether the candidate *is* the port or another Protocol); `implementations("AppServices")` "succeeded" against a plain (non-`Protocol`) class; `callers("repo_root")` was ambiguous with the `REPO_ROOT` constant because case-insensitive and case-exact matches were both kept as ties; webnav `diagnostics` false-flagged `.gallery-loading-spinner`/`.resolution-*` as unreferenced (markup inside JS string literals wasn't scanned, and a dynamically-built class/id via string concatenation was never credited as a reference); and `selector("#view-components")` missed the `"view-" + resolved` dynamic hit stored under the shorter `#view-` key. Separately, the user flagged wanting to potentially release `codenav`/`webnav` as standalone tools for other projects, and asked to avoid hardcoding more SpaceMaker-specific structure than necessary while fixing these.
- **Decision:** Bug fixes: (1) `implementations` now excludes the port itself (same file+name) and any candidate that is itself a `Protocol` (via new `_protocol_class_names()`, AST-based since `documentSymbol` doesn't expose base classes), and rejects a non-`Protocol` `port_name` with an explanatory message up front. (2) `_shared/resolve.py`'s `_exact_candidates()` keeps only case-exact (tier-0) hits when any exist, falling back to case-insensitive only when there's no exact-case match. (3) `web_index.py`: widened `_ID_ATTR_RE`/`_CLASS_ATTR_RE` to run over JS string literals too (`_scan_markup_attrs` shared between HTML and JS scanning); `_literal_tokens()` tags the trailing whitespace-split token of a class-list string as a dynamic prefix when a `+` concatenation follows and the literal doesn't end in whitespace; `unreferenced_selectors()` and the new `_dynamic_prefix_hits()` helper treat a dynamic hit as a reference for any longer token it's a prefix of. (4) `format_selector()` uses the same `_dynamic_prefix_hits()` to surface those as "dynamic partial match via '<prefix>'" alongside exact hits. (5) Nit: new `format_references()` (`_shared/format.py`, `DEFAULT_REFERENCES_SNIPPET_LIMIT = 8`) gives full snippets at/under the limit and a compact `L<line>:<col>` grouped list above it; used by both servers' `references` tool.
  Portability: replaced every hardcoded SpaceMaker path in the server source with an env-var override defaulting to a generic behavior, mirroring the existing `CODENAV_MCP_WORKSPACE`/`WEBNAV_MCP_WORKSPACE` pattern — `CODENAV_MCP_SOURCE_ROOT` (codenav's candidate-scan root for `implementations`, default: whole workspace) and `WEBNAV_MCP_ROOTS` (webnav's `label=relative/path` root list for `web_index.build_workspace_index`, default: one unnamed root over the whole workspace). SpaceMaker's own `src` / `static=…,wireframes=…` values now live only in `.mcp.json`/`.cursor/mcp.json`, not in `mcp-servers/` source. `web_index.py`'s old `STATIC_ROOT_REL`/`WIREFRAME_ROOT_REL` module constants and hardcoded `"static"`/`"wireframes"` labels in formatting output were removed entirely in favor of the generic `(root, name)` shape `RootIndex`/`build_root_index` already supported.
- **Rationale:** The self-match and non-Protocol-acceptance bugs made `implementations` actively misleading rather than merely incomplete, so they were fixed as correctness bugs, not deferred. The dynamic-prefix-as-reference change is an intentional behavior flip (a dynamically-built selector's runtime value plausibly matches a longer token sharing its static prefix), accepted as a tradeoff of occasional false negatives for not crying wolf on every dynamic id/class pattern already present in `app.js`. The portability generalization was scoped tightly to what the bug fixes already touched (no speculative new abstraction layer) — same override-with-default shape the codebase already used for workspace root resolution, so it added no new pattern to learn, just extended the existing one to the two remaining hardcoded assumptions.
